
COMP5047 – UniDorm Software Engineering Coursework

Project

This repository contains the group’s software engineering coursework for COMP5047: Applied Software Engineering.

The project is based on UniDorm, a multi-tenant software-as-a-service cloud-native application for the management and operation of university dormitories.

No software implementation is required. The coursework focuses on requirements analysis, UML modelling, software architecture and detailed design.

Coursework Tasks

Task 1 – Project Management

The team will establish and document the project management approach, including team structure, responsibilities, meetings and the team report.

Task 2 – Software Quality Requirements

Each member will define quality requirements for one functional requirement from their allocated subsystem.

The quality attributes covered are:

* Security and Privacy
* Performance
* Reliability
* Scalability

Task 3 – Functional Requirements Modelling

Each member will produce:

* One UML Use Case Diagram
* One UML Activity Diagram

The activity diagram will model one selected use case from the member’s subsystem.

Task 4 – Software Architectural Design

Each member will produce an architectural design for their subsystem.

The team will also integrate the subsystem architectures into a whole-system architecture.

The architecture will use UML component diagrams to represent microservices and APIs.

Task 5 – Software Detailed Design

Each member will select one component from their subsystem architecture and produce:

* One UML Class Diagram
* One UML Sequence Diagram

The sequence diagram will correspond to the same component selected for the class diagram.

Workflow

Branches

Use the following branch naming convention:

feature/<description>
docs/<description>
task/<task-number>-<description>
fix/<description>

Examples:

task/2-quality-requirements
task/3-use-case-diagram
task/4-accommodation-architecture
task/5-class-diagram
docs/team-report

Pull Requests

All significant work should be committed to a branch and submitted through a Pull Request before being merged into main.

Pull Requests should be reviewed by another team member where appropriate.

Commits

Use clear commit messages describing the change.

Examples:

Add quality requirements for accommodation allocation
Add accommodation office use case diagram
Update whole system architecture
Add class diagram for allocation service
Update team meeting minutes
